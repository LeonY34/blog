C. Find the Zero

Solution

有趣的小题。

首先，可以发现，只要评测机告诉你一次111，答案就是你问的两个中随便一个。

由于只有n+1n+1n+1次询问，所以有两个思考的方向：

  1. 全部询问都和某一个aia_iai​相关。但是只要aia_iai​是一个非000的就等于只得到了ai≠0a_i\neq 0ai​=0一个信息，肯定不够。
  2. 两两组成一对来问。

现在分析第二种：

  • 我们先花nnn次询问两两全部问好（第iii个和第i+ni+ni+n个绑定，且评测机报了nnn个000），那么我们就知道，每两个之间有一个000和一个非000；
  • 现在我们选择第nnn个和第111个，以及第nnn个和第n+1n + 1n+1个做两次询问。如果报的是两个000，那么第nnn个一定不是000，报告答案为2n2n2n；否则输出nnn即可。

这样就获得了一个n+2n+2n+2的方法。但是题目要求n+1n+1n+1，可以尝试优化。

现在我们现不问(n,2n)(n, 2n)(n,2n)，保持询问(n,1)(n, 1)(n,1)和(n,n+1)(n, n+1)(n,n+1)，则

  • 由于前面n−1n-1n−1次询问都是000，所以我们可以确定，nnn和2n2n2n中一定有一个000，否则前面应当有111；
  • 如果(n,1)(n,1)(n,1)和(n,n+1)(n, n+1)(n,n+1)都是000，那么1. 如果nnn是000，那么111和n+1n+1n+1都不是000，则2n2n2n一定是000；2. 如果nnn不是000，那么2n2n2n一定是000。所以不管怎样2n2n2n都是000，直接报告2n2n2n即可。

这样就得到了n+1n+1n+1次的方法。

D. Ghostfires

Solution

按照r,g,br,g,br,g,b中000的数量分情况考虑：

  1. 只有一个不为000：最多再放一个；
  2. 只有两个不为000：两个交替放，直到回到情况111；
  3. 三个都不为000，则有两种情况：
    a. 如果三个数量相同，则类似RGB|GBR|BRG|...轮换放，可以全部放完（第一个RGB一定有办法放出，可见后续证明）；
    b. 如果三个数量不完全相同，每次放较多的两个直到三者相同，或者回到情况2。如果只有最多的多一个，先放一个最多的，然后回到三者相同的情况。

现在证明三个相同时，一定有合法的放法：

设当前字符串为sss。不失一般性，

  1. 假设sss的最后三个字母是RGB（如果∣s∣<3\left|s\right| < 3∣s∣<3，补到三个，后续去掉不会影响结论），那么加上GBR即可；
  2. 假设最后三个字母是RGR（如果∣s∣<3\left|s\right| < 3∣s∣<3，补到三个，后续去掉不会影响结论），则加上GRB即可。

所以不管sss之前怎么放，只要到了三者相同的情况，一定能全部放完。

Solution

所以我们直接拆到每一次询问，问题变成：

对于一个长度为nnn的字符串sss，求出$$\sum_{i=1}^n f(s[1:i])$$

令f[i]=f(s[1:i])f[i] = f(s[1:i])f[i]=f(s[1:i])，假设当前已经求出了f[1],f[2],⋯ ,f[i−1]f[1], f[2], \cdots, f[i - 1]f[1],f[2],⋯,f[i−1]，且假设f[0]=0f[0]=0f[0]=0，假设字符串ttt是满足：

  1. ∣t∣=m≤i\left|t\right| = m\leq i∣t∣=m≤i；
  2. ttt是sss的前缀，也是s[1:i]s[1:i]s[1:i]的后缀；
  3. ttt是满足条件1, 2的字符串中最短的一个。

那么我们就可以做更新：$$f[i] = f[i - m] + 1$$

证明：

假设存在一种分割方式，没有在i−m+1i-m+1i−m+1处做分割，那么这种分割方式的最后一次分割一定在i−m+1i-m+1i−m+1之前（如果在后面就不满足ttt的最短性质），所以我们添加一个i−m+1i-m+1i−m+1的分割，一定是更优的，矛盾。

回顾KMP，它做的是满足条件1, 2的字符串中，最长的一个。那么我们不停的跳失配指针，直到跳到000之前，获得的应该就是最短的（如果不是最短的，那么不应该跳到000）。

F. Dynamic Values And Maximum Sum

Solution

最重要的observation：取完第一次后，所有的value都集中在叶子结点，后面再怎么取，value都不会改变。

所以问题转化为：挑选一个跟节点rrr，让除了rrr以外的所有节点都跑到自己子树中，离自己最远，且编号最小的节点去，然后取前k−1k-1k−1大的value。

对于确定根情况下，每个点会跑到哪个节点去，是可以O(n)O(n)O(n)遍历求出来的。所以得到了一个简单的O(n2)O(n^2)O(n2)办法。

我们不妨先假设111为根节点，求出每个节点会跑到的节点。然后开始换根，每次根从uuu换到vvv的时候，只需要将uuu要到的节点改为vvv子树外离uuu最远的节点（这个可以通过上面传下来的+uuu子树内但非vvv子树内的部分合并求解）。

同时维护两个multiset：hihihi里面放较多的k−1k-1k−1个value，lololo里面放较少的n−k+1n-k+1n−k+1个value。每次换根的时候，从hihihi或者lololo里面重新erase再insert一下，然后维护一下hihihi比lololo大的性质，这一部分是O(log⁡n)O(\log n)O(logn)的。再维护一个sumsumsum，在hihihi和lololo变动时，sumsumsum也同步变动。这样就可以O(nlog⁡n)O(n\log n)O(nlogn)求解。
