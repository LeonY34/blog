回顾KMP算法

对于一个字符串sss，每一位的下标为1,2,⋯ ,n1, 2, \cdots, n1,2,⋯,n，则我们可以求出一个数组ppp，满足以下约定：

设sis_isi​表示sss前iii个字符构成的子串；
pip_ipi​表示sis_isi​的子串（不包括sis_isi​自身）中，最长的、且同时为sis_isi​的前后缀的子串长度。

这样的定义同时保证了pip_ipi​指向了sis_isi​的最长前后缀的最后一个字符。

考虑用O(n)O(n)O(n)时间求出这个ppp数组：

假设p0=0p_0 = 0p0​=0，且p0,p1,⋯ ,pi−1p_0, p_1, \cdots, p_{i - 1}p0​,p1​,⋯,pi−1​都已经求好，那么我们如下方法求pip_ipi​：

  1. 令j=pi−1j = p_{i - 1}j=pi−1​
  2. 如果j+1j+1j+1对应的字符和iii对应的字符相等，那么pip_ipi​就是j+1j+1j+1；
  3. 如果不满足(2)，且j=0j=0j=0，则pi=0p_i=0pi​=0；
  4. 如果(2)(3)均不满足，则j←pjj\leftarrow p_jj←pj​，回到(2)。

这样做的正确性是：

  1. 首先pi≤pi−1+1p_i \leq p_{i - 1} + 1pi​≤pi−1​+1，因为只要定了pip_ipi​，则往前推一格就能得到pi−1p_{i-1}pi−1​的下界；
  2. 同理，当pi−1+1p_{i-1}+1pi−1​+1和iii对应的字符不相等时，pi≤ppi−1+1p_i\leq p_{p_{i - 1}} + 1pi​≤ppi−1​​+1；
  3. 以此类推，所以只要不停地往前迭代ppp即可。

复杂度正确性：

ppp每次最多增加111，往前迭代过程中jjj每次最少减少111，所以总共最多迭代nnn次。

## AC自动机

问题引入

假设现在有nnn个字符串s1,s2,⋯ ,sns_1, s_2, \cdots, s_ns1​,s2​,⋯,sn​，要判断每个字符串是否是字符串ttt的子串。

如果用KMP算法，对于nnn个字符串求失配指针ppp，复杂度为O(n∑∣si∣)O(n\sum \left|s_i\right|)O(n∑∣si​∣)；分别跟ttt匹配，复杂度为O(∑∣t∣)=O(n∣t∣)O(\sum \left|t\right|) = O(n\left|t\right|)O(∑∣t∣)=O(n∣t∣)，复杂度为O(n(∑∣si∣+∣t∣))O(n(\sum \left|s_i\right| + \left|t\right|))O(n(∑∣si​∣+∣t∣))，当∣t∣\left|t\right|∣t∣很大时就GG了。

AC自动机算法

搞一个Trie，把所有sis_isi​都丢进去，其中根节点编号为000，设点uuu的子节点中，连着字符ccc的子节点为neu,cne_{u, c}neu,c​，没有则是000。

然后我们模仿KMP对字典树上每个节点求失配指针ppp。在树上进行一个BFS，每次求vvv节点的ppp时，深度小于vvv的节点都已经求好了。设uuu是vvv的父亲，(u,v)(u,v)(u,v)边对应字符为ccc，那么我们不停的找到pup_upu​，如果nepu,cne_{p_u, c}nepu​,c​存在，那么就找到了，否则一直取ppp。这样就可以找到所有点的ppp。

匹配的时候，如果uuu的下一个失配了，那么我们就跳到pup_upu​继续尝试匹配。

复杂度分析

建树这一步复杂度为O(nm×∑∣si∣)O(nm\times\sum\left|s_i\right|)O(nm×∑∣si​∣)，其中mmm表示字符数量。

但是求解失配指针的这一步好像炸缸了，可能会被卡到平方级（每次都往前跳O(n)O(n)O(n)下），但不知道为啥过了。

为了优化求失配指针的过程，我们不能再一直往前跳了，但是匹配的时候，由于要匹配的东西是一个线性结构，依然满足之前的均摊复杂度，只要保证每次跳完长度至少−1-1−1即可。

回顾一下需要往前继续跳的情况：nepu,c=0ne_{p_u, c}=0nepu​,c​=0。反正空着也是空着，我们不妨让nepu,c=neppu,cne_{p_u, c}=ne_{p_{p_u}, c}nepu​,c​=neppu​​,c​，这样就有个很有意思的结果：如果nenene不存在，那么nenene会指向第一个存在的失配指针，因为如果它指向的也不存在，那么那个不存在的会指向一个存在的（归纳）。

这样处理之后，我们就不需要跳了，直接设pv=nepu,cp_v = ne_{p_u, c}pv​=nepu​,c​就好了。

这样求解失配指针的复杂度就优化到了O(nm∑∣si∣)O(nm\sum\left|s_i\right|)O(nm∑∣si​∣)。

最后就是查询。以此题为例。

首先可以想到在每个trie的节点上开一个vector记录当前节点是哪些字符串的结尾。

对ttt进行匹配，目标字符串ttt对于第iii位匹配到节点uuu，则表示到uuu节点的路径的所有后缀都可以匹配到第iii位。给节点uuu打上标记vis[u]++，最后我们希望所有的pu,ppu,⋯p_u, p_{p_u}, \cdotspu​,ppu​​,⋯都可以继承vis[u]。

直接暴力跳会和之前一样复杂度爆炸，不如用拓扑排序（ppp数组建成的图当然是一个DAG）。

这样查询的复杂度是O(∣t∣)O(\left|t\right|)O(∣t∣)。

修改后也没快多少。

总的时间复杂度：O(nm∑∣si∣+∣t∣)O(nm\sum\left|s_i\right|+\left|t\right|)O(nm∑∣si​∣+∣t∣)，如果mmm可视为常数（比如说26），则复杂度是O(n∑∣si∣+∣t∣)O(n\sum\left|s_i\right| + \left|t\right|)O(n∑∣si​∣+∣t∣)，比KMP快，尤其是在∣t∣\left|t\right|∣t∣比较大的情况下。

但是当mmm不可忽略时还有待研究。可能可以使用类似map的东西，带一个log⁡\loglog的复杂度。
