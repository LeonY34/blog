树状数组

树状数组是一个比较简洁且实用的数据结构。它可以在 O(log⁡n)O(\log n)O(logn) 的时间复杂度和 O(n)O(n)O(n) 的空间复杂度（均为小常数）下支持单点修改和前缀询问的操作。在满足可减性的情况下，可以支持区间询问。

可以说树状数组是线段树的阉割版，但是它有着非常优秀的性能，代码实现难度也非常低。

详见树状数组。

线段树

简介

线段树是一个功能强大的数据结构，它的基本用途就是在单次操作 O(log⁡n)O(\log n)O(logn) 的时间内维护序列区间信息。它可以支持区间修改，区间查询（满足结合律的情况下）。

线段树是一棵二叉树。它的每个节点都代表了一个区间，其中根节点存放了整个序列的信息总和。每一个节点要么是叶子结点，要么有两个儿子。叶子结点代表了一个长度为 111 的区间，非叶子结点代表的区间是两个儿子节点代表区间的总和。

形象化地，一棵长度为 999 的线段树长这样：

上图中每个黑框表示了一个节点，红色数字表示了每个节点代表的区间，绿线表示父子关系。

结构分析

从上图可以看出，每个节点的两个儿子尽可能均匀地划分了父亲代表的区间且刚好不重不漏，这保证了线段树的深度是 O(log⁡n)O(\log n)O(logn) 级别。

同时，这种方法的空间复杂度是 O(n)+O(n2)+O(n4)+...=O(n)O(n) + O(\frac{n}{2}) + O(\frac{n}{4})+... = O(n)O(n)+O(2n​)+O(4n​)+...=O(n) 的。

值得注意的是，虽然在节点数量为 222 的整次幂时线段树刚好是一棵完美二叉树，在大部分情况下线段树会有一层不满的情况。

我们不难发现，线段树是一个递归的结构，所以我们在实现的时候常常使用递归的实现。

操作 1：单点修改，区间查询

先来看一道题：

问题 1：给定有 nnn 项的序列 a1,a2,a3,...,ana_1, a_2, a_3, ..., a_na1​,a2​,a3​,...,an​ 。
现在有 mmm 次操作，每次操作是下面两种之一：
1.给定 x,yx, yx,y ，将 axa_xax​ 加上为 yyy 。
2.给定 l,rl, rl,r ，求出 al+al+1+al+2+...+ara_l + a_{l+1} + a_{l+2} + ... + a_ral​+al+1​+al+2​+...+ar​ 。
1≤n,m≤1051\leq n, m\leq 10^51≤n,m≤105 。

显然可以用一个非常普通的数组维护这个操作。不过对于第二个操作，我们需要从 lll 到 rrr 扫一遍，复杂度 O(n)O(n)O(n) ，太浪费时间了。我们当然可以使用树状数组解决这个问题，不过现在我们要学习的是线段树。为了做出这道题，我们需要考虑以下问题。

  1. 线段树的每一个节点需要维护什么信息？

很自然的想法就是让每个节点维护它所代表的区间的数之和。令 TkT_kTk​ 表示节点 kkk 所代表的区间的数之和。如果 kkk 是叶子结点，那么 TkT_kTk​ 就是它代表的数的值。如果 kkk 是非叶子节点，假设其左儿子为 lslsls ，右儿子为 rsrsrs ，很明显有 Tk=Tls+TrsT_k = T_{ls} + T_{rs}Tk​=Tls​+Trs​ 。

所以理论上只要我们知道了所有叶子结点的值，就可以知道整棵树的值了。于是我们可以递归地建树，初始化所有节点的信息。

我们假设原始序列为 1,2,1,2,1,2,1,2,11, 2, 1, 2, 1, 2, 1, 2, 11,2,1,2,1,2,1,2,1 ，则建出来的树长这样：

蓝色数字表示节点存放的信息。

  1. 如何进行操作 111 ？

每次要更新单点的信息时，只需要通过树边走到指定的叶子节点更新信息就好了。显然复杂度和树深度相同，是 O(log⁡n)O(\log n)O(logn) 的。

如何更新节点信息？对于叶子结点，直接更新。对于非叶子结点，运用之前的等式 Tk=Tls+TrsT_k = T_{ls} + T_{rs}Tk​=Tls​+Trs​ 就好了！因为只有途经的节点的信息会受到影响，所以我们只要在更新完叶子结点之后回溯时顺带更新即可。

如图，如果要让 a2a_2a2​ 加上 111 的话，灰色节点会发生改变，而白色节点不改变。

  1. 如何进行操作 222 ？

线段树建这么多层节点到底有什么用？在区间操作的时候我们就会发现它的方便之处了。

如果要查询的区间刚好是线段树上的一个区间，那好办，直接搜索到这个区间，然后返回值就好了。显然复杂度依然是 O(log⁡n)O(\log n)O(logn) 。

但更多情况下，查询的区间并不是线段树上完整的区间。这时，只需将该区间拆分成若干个线段树上的节点，再合并就行了。

比如说要查询 [2,8][2,8][2,8] 的话：

其中浅灰色节点表示途经而不加入计算的节点，深灰色节点表示加入计算的节点。

咋一看好像查询一次几乎覆盖了整棵树，复杂度会不会出问题呢？

但是，可以证明，单词查询复杂度依然是 O(log⁡n)O(\log n)O(logn) 的。

证明如下：

首先，定义加入计算（完全包含于查询区间且父亲不是完整节点）的节点为完整节点，定义在递归过程中（和查询区间有交集但不包含于查询区间）的节点为途经节点。

由于途经节点一定不包含于查询区间，又和查询区间有交集，故对于同一层的途经节点，一定只有一个或两个（即直接包含查询区间，或者一个跨过查询左端点、一个跨过查询右端点）。

那么完整节点的数量有多少呢？显然只有途经节点才会递归下去，那么最坏情况是这一层有两个途经节点，导致下一层有两个完整节点加上两个途经节点。换言之，由于每一层最多有两个途经节点，所以下一层最多只有四个节点，不管是完整节点还是新的途经节点。每层最多只会遍历四个节点，层数又是 O(log⁡n)O(\log n)O(logn) 的，所以节点总数为 O(4⋅log⁡n)=O(log⁡n)O(4\cdot\log n)=O(\log n)O(4⋅logn)=O(logn) 。

这只是理论复杂度，实际上不需要考虑 444 这个常数，因为经常跑不满。

一些习惯记法

为了为后面的代码实现做准备，我们规定一些习惯。

  • T[k]T[k]T[k] 表示 kkk 点的信息。

  • 根节点为 111 ，节点 kkk 的左儿子是 2k2k2k ，右儿子是 2k+12k + 12k+1 。在程序中，可简写为 k<<1 和 k<<1|1 。

这样节点会不会重复使用编号呢？不会的。如果我们考虑 kkk 的二进制表示，那么 2k2k2k 相当于在它后面加了一个 000 ， 2k+12k + 12k+1 相当于在它后面加了一个 111 。

注意，由于线段树有时不是完美二叉树，我们需要将空间开到序列大小的四倍！

  • 区间 [l,r](l<r)[l,r](l<r)[l,r](l<r) 的两个儿子区间为 [l,mid][l, mid][l,mid] 和 [mid+1,r][mid + 1, r][mid+1,r] 。其中 mid=⌊l+r2⌋mid = \lfloor\frac{l + r}{2}\rfloormid=⌊2l+r​⌋ （ ⌊x⌋\lfloor x\rfloor⌊x⌋ 表示 xxx 向下取整）。

这样可以保证区间尽可能均匀划分，又不会划分出空区间。

懒标记

接下来是线段树的精髓：懒标记。这里只介绍标记下传法。

问题 2：给定有 nnn 项的序列 a1,a2,a3,...,ana_1, a_2, a_3, ..., a_na1​,a2​,a3​,...,an​ 。
现在有 mmm 次操作，每次操作是下面两种之一：
1.给定 x,y,zx, y, zx,y,z ，将 ax,ax+1,ax+2,...,aya_x, a_{x+1}, a_{x+2}, ..., a_yax​,ax+1​,ax+2​,...,ay​ 加上为 zzz 。
2.给定 l,rl, rl,r ，求出 al+al+1+al+2+...+ara_l + a_{l+1} + a_{l+2} + ... + a_ral​+al+1​+al+2​+...+ar​ 。
1≤n,m≤1051\leq n, m\leq 10^51≤n,m≤105 。

这个问题就是线段树 1。

显然，如果我们把区间内所有节点都修改一遍，那复杂度就变为了 O(n)O(n)O(n) ，不如暴力。

然而，根据区间查询的思想，我们不妨将修改的区间也拆分成线段树上的节点。这样的节点有 O(log⁡n)O(\log n)O(logn) 个。

但问题是，如果我们只更新这些节点，那当我们查询到这些节点子树内的节点时，就寄了。

但是我们发现，我们每次操作遍历的节点永远都只有 O(log⁡n)O(\log n)O(logn) 个。所以我们可以在修改一个区间时标记一下这个区间，当要用到此区间的子节点时，将标记传给子节点即可！这就是懒标记。一个节点 kkk 的懒标记记为 lz[k]lz[k]lz[k] 。

比如说我要将 [1,2][1,2][1,2] 增加 111 时，只需要将代表 [1,2][1,2][1,2] 的节点 kkk ，即 T[k]T[k]T[k] ，增加 111 ，然后将 lz[k]lz[k]lz[k] 也增加 111 ，然后直接回溯。当我们再次走到 [1,2][1,2][1,2] 时，我们将 [1,1][1,1][1,1] 的 TTT 和 lzlzlz 增加 111 ，将 [2,2][2,2][2,2] 的也都增加 111 就好了。这是标记下传的操作。

动态开点线段树

问题 3：有 nnn 项的序列 a1,a2,a3,...,ana_1, a_2, a_3, ..., a_na1​,a2​,a3​,...,an​ 初始值全部为 000 。
现在有 mmm 次操作，每次操作是下面两种之一：
1.给定 x,y,zx, y, zx,y,z ，将 ax,ax+1,ax+2,...,aya_x, a_{x+1}, a_{x+2}, ..., a_yax​,ax+1​,ax+2​,...,ay​ 加上为 zzz 。
2.给定 l,rl, rl,r ，求出 al+al+1+al+2+...+ara_l + a_{l+1} + a_{l+2} + ... + a_ral​+al+1​+al+2​+...+ar​ 。
1≤n≤109,1≤m≤1051\leq n\leq 10^9, 1\leq m\leq 10^51≤n≤109,1≤m≤105 。

显然，如果我们依然和以前一样建树的话，肯定会爆空间，因为序列实在是太长了。对此，我们可以使用离线离散化，把操作中的端点抽出来，然后再建树，这样复杂度可以做到 O(mlog⁡m)O(m\log m)O(mlogm) 。然而如果我们懒得离散化，或者题目强制在线的话，就可以采用动态开点线段树。

现在我们假设还是和原来一样建树。由于每个操作只会遍历 O(log⁡n)O(\log n)O(logn) 个节点，所以实际上遍历用到的节点只有 O(mlog⁡n)O(m\log n)O(mlogn) 个。也就是说，大部分的节点都是废物节点，完全用不着。这启示我们可以用一个点加一个点，从而节省空间。

既然要动态地开点，我们的左儿子和右儿子显然不能再是 2k2k2k 和 2k+12k+12k+1 了。我们得单独开一个数组来记录一下。记 kkk 的左右儿子分别为 son[k][0/1]son[k][0/1]son[k][0/1] 。

代码实现的时候，我比较喜欢使用取地址的方式。注意，该方式可能不适用于 vectorvectorvector ，会出现不可预知的错误。建议预估空间开数组来存。

时间复杂度依然是 O(mlog⁡n)O(m\log n)O(mlogn) 。

权值线段树

问题 4：有一个空序列，
现在有 mmm 次操作，每次操作是下面两种之一：
1.给定 xxx ，在序列末尾加入 xxx 。
2.给定 xxx ，求出 xxx 在序列中的排名（比 xxx 小的数的个数 +1+1+1 ）。
1≤m,x≤1051\leq m, x\leq 10^51≤m,x≤105 。

咋一看好像不是个线段树的题。写个平衡树或者直接全部丢到 setsetset 里就完事了。但是我们想要使用线段树来完成这道题。

容易发现，序列中数的顺序没有用处，所以，以序列下标建树实为下策。而数之间的大小关系正是我们关心的。我们不妨转换一下思路——以数的值域建树，每个点存这个数出现的次数，也就是用线段树维护一个桶！这样一来，操作 222 就变成了 [1,x−1][1,x-1][1,x−1] 的和再 +1+1+1 。这显然是可以通过线段树或者树状数组维护的。

值得一提的是，当 xxx 的值域比较大时，我们可以结合动态开点解决这个问题。

这种以值域建树的线段树被称为权值线段树，因为它的每一个点存的是这个数的权值。

问题 5：有一个空序列，
现在有 mmm 次操作，每次操作是下面两种之一：
1.给定 xxx ，在序列末尾加入 xxx 。
2.给定 xxx ，序列中第 xxx 小的数。
1≤m≤105,1≤x≤1091\leq m\leq 10^5, 1\leq x\leq 10^91≤m≤105,1≤x≤109 。

继续建立动态开点权值线段树。对于操作 222 ，可以用问题 444 查排名的方法结合二分来解决，但是这样会产生两个 logloglog ，感觉比较慢。

我们不妨直接在线段树上二分。当到达一个节点的时候，我们观察一下：如果左儿子里面存的数的个数大于等于 xxx ，那么我们要找的数肯定在左边，就往左边走；否则肯定不在左边，那就往右边走。这样就可以做到一个 logloglog 的查询啦！

结合问题 444 和问题 555 ，我们可以用比较简洁的代码切掉普通平衡树。

不过这个复杂度是 O(mlog⁡x)O(m\log x)O(mlogx) ，毕竟还是比平衡树的 O(mlog⁡m)O(m\log m)O(mlogm) 要慢一些的（除了一些常数大的平衡树）。空间上也是 O(mlog⁡x)O(m\log x)O(mlogx) ，比较大。

分块

首先是序列分块。

顾名思义，序列分块就是将序列分成若干块，然后块内维护信息。当我们要进行查询时，只需要将序列中完整的块的信息全部加起来，然后再加上两端散点的信息即可。

设序列长度为 nnn ，分成 mmm 块，则块的长度为 O(nm)O(\frac{n}{m})O(mn​) 。区间查询时，整块部分的复杂度为 O(m)O(m)O(m) ，散点部分的复杂度为 2×O(nm)=O(nm)2\times O(\frac{n}{m}) = O(\frac{n}{m})2×O(mn​)=O(mn​) 。故总复杂度为 $O(m) + O(\frac{n}{m}) $ ，根据基本不等式，当 m=O(n)m = O(\sqrt n)m=O(n​) 时最优。事实上，分块的效率很受常数的影响，所以调整块长是降低常数的常用方式。

从一种观点来看，线段树本质上就是递归的分块。线段树的查询可以保证区间能被拆分成若干个整块，而分块不能。所以分块仍然需要暴力的处理。

分块是整体处理和单点处理的平衡。通俗的说，和根号分治一样，就是两个暴力拼起来。它的效率低于线段树，但能实现很多线段树不能实现的功能。

块长并非取 O(n)O(\sqrt n)O(n​) 最优，要视具体题目分析处理。
